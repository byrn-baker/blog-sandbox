# Golden Config — SP Demo Lab

This folder is the Git data source for Nautobot Golden Configuration. Nautobot
syncs from this repo to pull templates, store intended configs, and store backup
configs.

## Structure

```
golden-config/
├── templates/
│   ├── cisco_ios.j2              # IOS-XE template (SP core: P/PE/RR/CE/Border)
│   ├── arista_eos.j2             # EOS template (DC fabric: spines + leaves)
│   └── graphql_query.graphql     # GraphQL query for SoT aggregation
├── intended-configs/             # Generated by Golden Config (auto-populated)
│   └── <location>/<device>.cfg
├── backup-configs/               # Pulled from devices (auto-populated)
│   └── <location>/<device>.cfg
└── README.md
```

## Setup in Nautobot

### 1. Create GitHub Token Secret

Navigate to **Secrets** → Create:
- **Name:** `GITHUB_TOKEN`
- **Provider:** Environment Variable
- **Parameter:** `GITHUB_TOKEN`

Add to `environments/creds.env`:
```
GITHUB_TOKEN=ghp_your_token_here
NAPALM_USERNAME=admin
NAPALM_PASSWORD=admin
```

### 2. Create Secrets Group

- **Name:** `GitHub`
- **Access type:** HTTP(s)
- **Secret type:** Token
- **Secret:** Select your `GITHUB_TOKEN`

### 3. Create Git Repository

Navigate to **Extensibility → Git Repositories** → Create:

| Field | Value |
|-------|-------|
| Name | `blog-sandbox-golden-config` |
| Remote URL | `https://github.com/byrn-baker/blog-sandbox.git` |
| Branch | `main` |
| Secrets Group | `GitHub` |
| Provides | Jinja2 Templates, Intended Configs, Backup Configs |

**Important:** Set the base path to `golden-config/` since the templates aren't
at repo root.

### 4. Create GraphQL Query

Navigate to **Extensibility → GraphQL Queries** → Create:
- **Name:** `sp_demo_lab_golden_config`
- **Query:** paste contents of `templates/graphql_query.graphql`

### 5. Configure Golden Config Settings

Navigate to **Golden Config → Settings** → Edit default:

| Section | Field | Value |
|---------|-------|-------|
| Backup | Repository | `blog-sandbox-golden-config` |
| Backup | Path | `backup-configs/{{obj.location.name\|slugify}}/{{obj.name}}.cfg` |
| Intended | Repository | `blog-sandbox-golden-config` |
| Intended | Path | `intended-configs/{{obj.location.name\|slugify}}/{{obj.name}}.cfg` |
| Templates | Repository | `blog-sandbox-golden-config` |
| Templates | Path | `templates/{{obj.platform.network_driver}}.j2` |
| SoT Agg | Query | `sp_demo_lab_golden_config` |

### 6. Enable Golden Config Jobs

Navigate to **Jobs** → select all Golden Config jobs → Edit → **Enabled: Yes**

### 7. Generate Intended Configs

Navigate to **Golden Config → Tools → Generate Intended Configurations** → Run

## Template Design

### cisco_ios.j2 (IOS-XE)

Renders the full SP core config based on device role:
- **P-Router:** IS-IS + MPLS LDP (no BGP)
- **PE-Router:** IS-IS + MPLS LDP + BGP VPNv4/v6 + VRF PE-CE
- **Route-Reflector:** IS-IS + MPLS LDP + BGP VPNv4/v6 (with RR client config)
- **CE-Router:** BGP IPv4 unicast to PE
- **Border-Router:** IS-IS + MPLS LDP (external connectivity)

### arista_eos.j2 (EOS)

Renders the DC fabric config:
- **Spine:** eBGP underlay (IPv4) + eBGP overlay (EVPN) to all leaves
- **Leaf:** eBGP underlay + overlay to both spines, VXLAN interface

## Data Flow

```
Nautobot SoT (devices, IPs, BGP, ISIS)
         │
         ▼ GraphQL query
    Jinja2 template
         │
         ▼ renders
   Intended Config
         │
         ▼ compare against
    Backup Config (from device)
         │
         ▼
   Compliance Report (match / drift)
```
