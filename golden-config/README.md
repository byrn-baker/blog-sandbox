# Golden Config - SP Demo Lab

This folder is the Git data source for Nautobot Golden Configuration. Nautobot
syncs from this repo to pull templates, store intended configs, and store backup
configs.

## Structure

```
golden-config/
├── templates/
│   ├── cisco_ios.j2              # IOS-XE template (SP core: P/PE/RR/CE/Border)
│   ├── arista_eos.j2             # EOS template (DC fabric: spines + leaves)
│   ├── ios/                      # Modular IOS-XE partials
│   │   ├── hostname.j2
│   │   ├── vrfs.j2
│   │   ├── interfaces.j2
│   │   ├── isis.j2
│   │   ├── mpls.j2
│   │   └── bgp.j2
│   └── eos/                      # Modular EOS partials
│       ├── hostname.j2
│       ├── vrfs.j2
│       ├── interfaces.j2
│       ├── routing.j2
│       └── bgp.j2
├── intended-configs/             # Generated by Golden Config (auto-populated)
│   └── <location>/<device>.cfg
├── backup-configs/               # Pulled from devices (auto-populated)
│   └── <location>/<device>.cfg
└── README.md
```

## Setup in Nautobot

### 1. Create a GitHub Fine-Grained Personal Access Token

Generate a fine-grained PAT on GitHub with:

- **Repository access:** Select the `blog-sandbox` repo only
- **Permissions:**
  - Contents: Read and write
  - Metadata: Read-only (auto-selected)

No other permissions are needed. Contents read/write allows clone, pull, and
push (for intended configs and backups).

### 2. Add environment variables

Edit `nautobot-docker-compose/environments/creds.env`:

```bash
GITHUB_TOKEN=github_pat_your_token_here
GITHUB_USERNAME=x-access-token
NAPALM_USERNAME=admin
NAPALM_PASSWORD=admin
```

Restart the containers to pick up the new env vars.

### 3. Create Secrets in Nautobot

Navigate to **Secrets** and create two secrets:

**Token secret:**
- Name: `GITHUB_TOKEN`
- Provider: Environment Variable
- Parameters > Variable: `GITHUB_TOKEN`

**Username secret:**
- Name: `GITHUB_USERNAME`
- Provider: Environment Variable
- Parameters > Variable: `GITHUB_USERNAME`

### 4. Create a Secrets Group

Navigate to **Secrets > Secrets Groups** and create:

- Name: `GitHub`

Add two associations:

| Access Type | Secret Type | Secret |
|---|---|---|
| HTTP(s) | Token | `GITHUB_TOKEN` |
| HTTP(s) | Username | `GITHUB_USERNAME` |

Both entries are required for push operations. The username `x-access-token`
is the fixed value GitHub expects when authenticating with a fine-grained PAT.

### 5. Add the Git Repository

Navigate to **Extensibility > Git Repositories** and create:

| Field | Value |
|---|---|
| Name | `sp_demo_lab_golden_config` |
| Remote URL | `https://github.com/byrn-baker/blog-sandbox.git` |
| Branch | `main` |
| Secrets Group | `GitHub` |

Under **Provides**, check all that apply:

- [x] Config Context Schemas
- [x] Config Contexts
- [x] GraphQL Queries
- [x] Golden Config Properties
- [x] Backup Configs
- [x] Intended Configs
- [x] Jinja Templates

Click **Create & Sync**. All checked items should show green checkmarks.

### 6. Configure Golden Config Settings

Navigate to **Golden Config > Settings** and edit the default entry:

| Section | Field | Value |
|---|---|---|
| Backup | Repository | `sp_demo_lab_golden_config` |
| Backup | Path | `golden-config/backup-configs/{{obj.location.name\|slugify}}/{{obj.name}}.cfg` |
| Intended | Repository | `sp_demo_lab_golden_config` |
| Intended | Path | `golden-config/intended-configs/{{obj.location.name\|slugify}}/{{obj.name}}.cfg` |
| Templates | Repository | `sp_demo_lab_golden_config` |
| Templates | Path | `golden-config/templates/{{obj.platform.network_driver}}.j2` |
| SoT Agg | Query | `sp_demo_lab_golden_config` (synced from graphql_queries/) |

### 7. Enable Golden Config Jobs

Navigate to **Jobs**, select all Golden Config jobs, click **Edit Selected**,
set **Enabled: Yes**, and click **Apply**.

### 8. Generate Intended Configurations

Navigate to **Golden Config > Tools > Generate Intended Configurations**:
- Select both platforms (cisco_iosxe + arista_eos)
- Click **Run Job Now**

After completion, intended configs appear in `golden-config/intended-configs/`
organized by location, and are pushed back to the GitHub repo automatically.

## What Gets Synced from This Repo

| Nautobot Feature | Repo Folder | Notes |
|---|---|---|
| Jinja Templates | `golden-config/templates/` | Selected by platform network_driver |
| Backup Configs | `golden-config/backup-configs/` | Written by backup job, pushed to git |
| Intended Configs | `golden-config/intended-configs/` | Written by generate job, pushed to git |
| GraphQL Queries | `graphql_queries/` | Auto-imported as saved queries |
| Config Contexts | `config_contexts/` | Role-based and device-specific |
| Config Context Schemas | `config_context_schemas/` | JSON Schema validation |
| Golden Config Properties | `golden_config/` | Compliance features and rules |

## Template Design

### cisco_ios.j2 (IOS-XE)

Renders the full SP core config based on what data exists in the SoT:

- **P-Router:** IS-IS + MPLS LDP (no BGP)
- **PE-Router:** IS-IS + MPLS LDP + BGP VPNv4/v6 + VRF PE-CE with route targets
- **Route-Reflector:** IS-IS + MPLS LDP + BGP VPNv4/v6 (with RR client config)
- **CE-Router:** BGP IPv4 unicast to PE
- **Border-Router:** IS-IS + MPLS LDP (external connectivity)

All operational parameters (ISIS process name, BGP timers, BFD intervals, MPLS
settings, VRF route targets) come from config contexts, not hardcoded values.

### arista_eos.j2 (EOS)

Renders the DC fabric config:

- **Spine:** eBGP underlay (IPv4) + eBGP overlay (EVPN) to all leaves
- **Leaf:** eBGP underlay + overlay to both spines

BGP timers, ECMP settings, and EVPN multihop come from config contexts.

## Data Flow

```
Nautobot SoT (devices, IPs, BGP, ISIS)
    + Config Contexts (timers, BFD, route targets)
         |
         v  GraphQL query
    Jinja2 template
         |
         v  renders
   Intended Config
         |
         v  compare against
    Backup Config (from device)
         |
         v
   Compliance Report (match / drift)
```

## Troubleshooting

**Push fails with "Username for https://github.com":**
The Secrets Group is missing the Username entry. Add an HTTP(s) / Username
secret with value `x-access-token`.

**Template not found errors:**
Include paths must be relative to repo root, not the template directory.
Use `golden-config/templates/ios/hostname.j2` not `ios/hostname.j2`.

**Compliance rules fail to sync:**
YAML files must be lists (start with `- `), not single dicts. The feature
field must be `feature_slug` not `feature`.
